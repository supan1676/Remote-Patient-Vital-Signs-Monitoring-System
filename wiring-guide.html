🔗 Installed I2C Devices — OLED + 3 Sensors

The OLED and two measurement sensors share the primary Wire bus on GPIO 8 (SDA) and GPIO 9 (SCL) at 50 kHz. The MPU-6050 stays on its own Wire1 bus on GPIO 17 (SDA) and GPIO 18 (SCL) at 400 kHz.

BusPinsClockDevices
Wire (primary)GPIO 8 SDA / GPIO 9 SCL50 kHzSSD1306 0x3C, MAX30102 0x57, TMP117 0x48–0x4B
Wire1 (dedicated IMU)GPIO 17 SDA / GPIO 18 SCL400 kHzMPU-6050 0x68 or 0x69 only

TMP117 ADD strapping selects one of 0x48, 0x49, 0x4A or 0x4B. The firmware scans those addresses and verifies WHO_AM_I = 0x0117. No address is assumed without a successful initialization/read.

Not installed: SHT40 and MLX90614 are not part of this build. Their legacy paths are compiled out, no wiring is provided, they are not counted in active_max, and they are not required by the default firmware or its library set. Do not add either module for this build.

✅
Primary Bus — OLED + 2 Sensors

SSD1306 OLED, MAX30102 and 7SEMI TMP117 ES-12132 share GPIO 8/9. The clock remains at 50 kHz for the shared bus. The MPU-6050 is isolated on Wire1.

🔌
Dedicated IMU Bus

The MPU-6050 stays on GPIO 17/18 (Wire1). Do not move it to GPIO 8/9 and do not use GPIO 17/18 for other peripherals.

📳
SOS & Optional Haptics

The SOS button uses GPIO 5 with INPUT_PULLUP and active-LOW logic. The current firmware does not drive a vibration motor; if one is added later, use a free GPIO with a MOSFET driver, never GPIO 17/18.

🧪
TMP117 Raw-Register Diagnostic
Separate PlatformIO project • no Adafruit TMP117 library

Run this before trusting the main firmware temperature. It scans the bus, checks WHO_AM_I, configuration, offset, raw MSB/LSB bytes and the signed conversion, and flags 0xFFFF, 0x0000, data-not-ready and read errors.

pio run -d diagnostics/tmp117_raw pio device list pio run -d diagnostics/tmp117_raw -t upload --upload-port COMx pio device monitor -d diagnostics/tmp117_raw --port COMx
📌 Capture at least five minutes, including the period where the normal firmware previously showed about -0.01 °C. Save the complete log; it contains only sensor diagnostics, no patient identifiers.
⚠️ If WHO_AM_I is not 0x0117, the bus does not ACK, configuration readback does not match 0x01A0, or raw 0xFFFF/0x0000 appears, stop and inspect power, ground, solder joints, pull-ups, address strapping and GPIO 8/9 wiring. Do not treat those readings as temperature.

⚡ System Architecture — Complete Wearable

ℹ️
Primary I2C Bus Clock & Power
50 kHz shared by OLED + MAX30102 + TMP117

The SSD1306, MAX30102 and TMP117 all run from the ESP32-S3's 3.3V rail. Standard breakouts include pull-up resistors; do not add extra pull-ups unless the bus fails to idle high.

I2C Speed Note: The shared primary bus stays at 50 kHz for timing margin and bus reliability. This applies to every device on GPIO 8/9. Do not raise the bus to 400 kHz globally; the firmware re-asserts 50 kHz after sensor and OLED transactions.

🌡️
TMP117 Placement
Actual sensor reading; clinical wrist contact unverified

The TMP117 measures its own package/board temperature. Keep it away from the ESP32-S3 regulator, battery, charging circuit and direct sunlight. Thermal contact, skin coverage, ambient airflow and movement all affect the value.

The actual reading is tmp117_sensor_temperature_c, displayed as TMP117 Sensor Temperature (°C). The clinical field wrist_skin_temperature_c, displayed as Wrist Skin Temperature (°C), stays unavailable while contact is unverified. Neither field triggers a fever decision. No SHT40 or MLX90614 channel exists in this build.

🔥
Vibration Motor Direct GPIO
Will burn your ESP32-S3

A coin vibration motor draws 60–100mA at startup. ESP32-S3 GPIO pins are rated for maximum 40mA (recommended ≤20mA).

Additionally, DC motors generate inductive kickback — voltage spikes when the motor turns off — that can destroy the GPIO pin.

Fix: Use a 2N7000 N-channel MOSFET (or 2N2222 NPN transistor) to switch the motor, with a 1N4148 flyback diode across the motor terminals. Or buy a "vibration motor module" that includes the driver circuit on the board.

🖐️
MAX30102 Wrist Placement
Won't work reliably on bare wrist

The MAX30102 uses Red (660nm) + IR (880nm) LEDs. These wavelengths need thin tissue with dense capillaries (fingertip, earlobe).

On the wrist, thick skin + fat + tendons + bone scatter the signal. Commercial smartwatches use green LEDs (~530nm) with custom optics and heavy DSP — technology the bare module doesn't have.

Fix: Mount the MAX30102 as a finger-clip probe connected via a short cable to the wrist unit. This gives cleaner optical readings with minimal code complexity; it does not make the prototype a certified clinical device.

🤚
Wrist Fall Detection False Alarms
Arm swings trigger >2.5G spikes

A simple acceleration threshold is often used for belt/waist fall prototypes, but it still requires validation. On the wrist, clapping, slamming a hand on a table, or swinging your arm quickly all exceed 2.5G.

Current firmware: a free-fall interval followed by a >2.5 g impact produces a candidate alert. This still false-alarms on wrist gestures and is not clinically validated.

Not implemented: impact spike followed by several seconds of near-zero angular velocity on the gyroscope. Any such change needs wrist-specific data and HARDWARE VERIFICATION REQUIRED before it is treated as reliable.

🌡️
Skin Temperature Is Not Core Temperature
Never add a fixed offset

The actual TMP117 sensor reading and the clinical wrist observation are different quantities. Wrist/contact temperature is typically well below the ~37°C core temperature patients and clinicians expect. That difference is physiological, not a sensor fault.

Do not add a fixed offset such as temperature + 3.0. The required correction varies with person, ambient temperature, placement and blood flow, so a constant offset produces a misleading number. The firmware reports tmp117_sensor_temperature_c as actual sensor telemetry and keeps wrist_skin_temperature_c null until contact is verified.

Core temperature and fever screening remain unavailable. The exact dashboard message is Core temperature unavailable — confirmation required. Use a validated clinical thermometer and clinician assessment when core temperature is required.

📊
Validity States & Limitations
Null is not zero, and a gap is not a line

Clinical wrist contact uses valid, warming_up, low_quality, stale, sensor_error, not_available or unverified. The actual TMP117 sensor uses the same hardware states except unverified. Any state other than valid produces JSON null; the dashboard and CSV leave the gap blank instead of drawing through it.

MAX30102: PART_ID must be 0x15; contact and signal quality are checked before HR/SpO2 are exposed. Accuracy is HARDWARE VERIFICATION REQUIRED. MPU-6050: configured for ±8 g and ±250 dps, with basic stationary bias only, not a full six-face calibration. Fall detection is a candidate alert, not a diagnosis.

📌
MPU6050 AD0 Pin
Intermittent I2C failures if left floating

The AD0 pin determines the I2C address (LOW = 0x68, HIGH = 0x69). If left unconnected (floating), it picks up electrical noise and randomly switches between addresses.

Result: MPU6050 works sometimes, fails randomly. Hard to debug because it seems intermittent.

Fix: Always tie AD0 to GND with a wire. This costs nothing and permanently fixes the address to 0x68.
